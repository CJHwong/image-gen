# Drama-3 capabilities and fit for Voice studio

Study date: 2026-10-21. This report separates model features from the MLX port's public features.
Documentation and source were inspected, then the 8-bit checkpoint was tested on the office M5 Pro (64 GiB).
The Voice integration now supports Generate and Clone through the shared UI and API.
The measured results below distinguish first use, warm calls, and incomplete speech.

## Place in the current UI

Keep Drama-3 inside Voice studio as another model choice.
Reuse the current player, waveform, range selection, metadata, action menu, gallery, and shared operation state.
One script still produces one continuous clip by default.
Do not restore sentence splitting to support this model.

| Existing control or flow | Drama-3 fit | UI behavior |
|---|---|---|
| Script | Supported | Keep the Script field. Accept inline delivery cues. |
| Clone | Supported by MLX | Keep the reference card, recording, clear button, and gallery handoff. |
| Reference transcript | Required by MLX, absent from the current reference card | Add a transcript field for uploaded or recorded references. Prefill it from known generated scripts. |
| Reference audio quality | Uploaded references currently convert to 24 kHz | Keep the reference bandwidth needed by Drama-3 at 44.1 kHz. This needs an input-pipeline change. |
| Design | Plain synthesis and inline delivery cues work; AuK-style voice design remains unproved | Test voice identity control before exposing an equivalent Design mode. |
| Voice description | No separate `instruct` argument in MLX | Do not send AuK's description unchanged. Test a template that inserts a direction before the script. |
| Templates | Suitable for delivery cues | Keep the Templates component. Supply Drama-3 templates with its own fields and syntax. |
| Edit | Full model supports edits; public MLX generation does not expose them | Leave Edit out until the selected engine proves the required behavior. |
| Duration | No equivalent target-duration control | Show automatic duration. Do not imply that a token limit sets an exact clip length. |
| Chinese characters | Current conversion exists for AuK pronunciation faults | Test Drama-3 before selecting any conversion default. Preserve the original script. |
| Playback speed | A player feature | Keep it. The model's lack of a speed argument does not affect playback speed. |
| Waveform, selection and clip actions | Ordinary audio output | Keep the current components and behavior. |
| Send to Video or Clone | Ordinary audio output | Keep these items in the action menu. |
| Generation preview | MLX can stream audio chunks | Keep the animation. Show elapsed time and generated audio length. Do not calculate completion from a token cap. |
| API batches | Repeated calls can share loaded weights and reference caches | Keep batch requests separate from speaker count. Do not claim parallel MLX generation yet. |

The Design row is an unresolved capability, not proof that the model cannot design voices.
The reference converter now follows each backend: 24 kHz for AuK and 44.1 kHz for Drama-3.
The MLX port documents 44.1 kHz output and warns that low-bandwidth references produce duller speech.
The reference card can stay the same while its conversion follows the selected model.
[Reference bandwidth documentation](https://github.com/Blaizzy/mlx-audio/blob/main/docs/models/tts/fish-drama3.md).
Inline performance direction and deliberate creation of a new voice identity need separate checks.
Fish's hosted Voice Design endpoint uses a separate `voice-design-1` model.
That service does not establish the open Drama-3 checkpoint's voice-design contract.
[Voice Design guide](https://docs.fish.audio/features/voice-design).

The inspected MLX `generate()` method requires a transcript for each supplied reference.
It rejects a separate instruction and non-default generation speed.
It exposes streaming and multiple references, but no public edit-history or batch method.
[MLX source at the inspected revision](https://github.com/Blaizzy/mlx-audio/blob/2209e6d76c18d0a24f7ff64d35b4176258acd909/mlx_audio/tts/models/fish_drama3/drama3.py).

## Additional capabilities and the design they need

| Capability | Current UI coverage | Possible addition |
|---|---|---|
| Line delivery, such as a whisper or tired speech | Templates can cover a whole line | Use reusable delivery templates with editable fields. |
| Sounds and pauses inside speech | The Script field can contain tags | Start with examples. Add an insert menu only if tag entry proves awkward. |
| Emphasis on selected words | No script-selection action | A later script toolbar can wrap selected words. |
| Pronunciation for names and terms | Chinese conversion cannot express this | A pronunciation editor can insert phoneme tags. |
| Multiple speakers | One reference card | Add speaker rows with a name, reference, and transcript. Keep one output clip. |
| Voice consistency in long scripts | One continuous clip already fits | Keep internal chunks out of the gallery. Check boundaries and missing words. |
| Revision with earlier takes | Current Edit uses an audio reference and instruction | Needs engine support for prior context and a clear source clip. |
| Local infilling | A selected waveform range exists | Requires an engine that exposes precise replacement. A range selector alone does not implement it. |

Fish documents free-text bracket cues, paired delivery tags, phoneme tags, and speaker tags.
Language switches within a line remain experimental.
[Performance guide](https://docs.fish.audio/features/text-to-speech/drama-3).

The full model advertises multi-turn revisions and speech infilling.
These features do not automatically exist in every deployment engine.
[Model repository](https://github.com/fishaudio/fish-speech), [technical report](https://arxiv.org/abs/2610.18010).

Drama-3 chooses output length during generation. A maximum token count is a limit, not a known endpoint.
Inference: single-clip progress should show elapsed time and generated audio length.
Batch progress can still show completed items out of the requested count.

Multiple speakers and multiple outputs are different operations.
A two-speaker scene can remain one clip with one waveform and one gallery item.
Sixteen batch items instead produce sixteen independent clips.

## What the first integration would include

1. Add Drama-3 to the existing model selector.
2. Keep the current gallery, player, range actions, and shared status behavior.
3. Prove plain generation, cloning, and reusable delivery templates.
4. Add reference transcripts where the engine requires them.
5. Use automatic duration and model-specific mandatory fields.
6. Keep one loaded engine and reuse encoded references across batch items.

The initial integration is implemented. Unsupported editing, scene composition, and hosted services remain outside its capability declaration.

The first integration would leave out scene composition, pronunciation editing, local infilling, and revision history.
Those features need separate designs and engine checks.
It would also leave out hosted voice libraries and hosted voice design.
Those services are not part of the downloaded Drama-3 model.

## Questions the 8-bit trial should answer

1. Does inline direction control delivery without speaking the direction aloud?
2. Can it create a specified voice identity without a reference?
3. Does cloning preserve the reference voice and all script words?
4. Does Traditional Chinese need conversion, phoneme hints, or neither?
5. Do long scripts remain complete and consistent as one clip?
6. Does repeated use recover memory and reuse reference encoding?

The user authorized the 8-bit trial and autonomous performance checks on 2026-10-21.

## Measured first trial

Checkpoint: `mlx-community/fish-audio-drama-3-8bit` at
`fedc7cc92bab5a180709cbaae6208d10b390bb97`; MLX Audio at
`2209e6d76c18d0a24f7ff64d35b4176258acd909`.
These measurements used one GPU job at a time.

| Primitive | Output duration | Generation time | Result |
|---|---:|---:|---|
| Plain English, first generation after load | 3.48 s | 16.00 s | Complete script |
| Whisper cue | 3.07 s | 2.72 s | Complete script |
| Emotional cue | 4.09 s | 4.66 s | Complete script |
| English clone, new reference | about 3.58 s | 6.68 s | Complete script |
| English clone, cached reference | about 3.39 s | 3.87 s | Complete script |
| Longer English line | 12.96 s | 11.18 s | Complete script |
| Unconditioned Traditional Chinese | 47.55 s | 48.23 s | Incomplete; reached 1,024-token cap |

Primitive model load was 20.61 s. Peak Metal allocation was about 41.4 GiB.
CPU transcription checked the six English outputs; this does not replace listening tests.
The Chinese output contained only the beginning of the script and is not a successful result.

Through the actual Studio API, four warm plain-English calls took 8.62 s individually
and 8.49 s as one batch (10.59 s of audio). Each corresponding PCM hash matched.
This is a 1.5% elapsed-time reduction, not proof of parallel engine batching.
The first fresh-runtime API call took 191.27 s and must be reported separately.
A 573-character unconditioned English script also reached the token cap.
The adapter rejects capped or internally incomplete speech rather than publishing it as complete.

The integration keeps weights resident, caches reference conditioning, bounds the allocator cache,
and decodes streaming chunks before joining one native-rate WAV. Drama-3 currently has two
validated short delivery templates. Multispeaker scenes, infilling, and voice identity design
remain unproved in this MLX path. Reference clips are limited to 15 seconds.

## Technical background

## Apple Silicon options

Fish's reference runtime requires NVIDIA hardware and at least 48 GB of GPU memory.
It does not support Apple MPS or CPU inference.
[Reference requirements](https://github.com/fishaudio/fish-speech/blob/main/docs/en/install.md).

MLX Audio provides an Apple Silicon port and converted weights:

| Variant | Published checkpoint size | Published peak memory |
|---|---:|---:|
| 4-bit experts, 8-bit dense layers and tower | About 22 GB | About 26 GB |
| 8-bit experts, remaining weights in bfloat16 | About 42 GB | About 49 GB |
| bfloat16 | About 67 GB | About 74 GB |

These figures come from the port's documentation, not my measurements.
The reported 4-bit speed on an M3 Max is about twice playback speed.
The port reports first audio below 200 ms with a cached reference and a short first chunk.
These figures describe different workloads and must not become an office-machine estimate.
[MLX Audio documentation](https://github.com/Blaizzy/mlx-audio/blob/main/docs/models/tts/fish-drama3.md).

The office machine has 64 GiB of unified memory.
My assessment: 4-bit leaves more working room. The user selects 8-bit for the first real test.
Full bfloat16 exceeds the published memory budget for this machine.

A second port, drama3-mac, uses MLX for generation and PyTorch for its codec.
It reports warm sequential batches and a 27.3 GB peak for its 4-bit model on an M3 Ultra.
It has a separate dependency stack and smaller acceptance evidence.
[drama3-mac](https://github.com/JordiPosthumus/drama3-mac).

## Source inspection and API limits

I read MLX Audio revision `2209e6d76c18d0a24f7ff64d35b4176258acd909`.
Its public `generate()` method supports reference audio with transcripts, multiple references, inline direction, and streaming.
It caches encoded references and their prompt prefix for four recent reference sets.
Long text uses internal chunks and keeps the first and latest chunks as context.

The public method does not expose previous takes, editing instructions, or a batch method.
Its separate `instruct` field raises an error. A generation speed other than 1.0 also raises an error.
Internal chunk history does not establish support for user-directed edits.
Its result field `real_time_factor` measures audio seconds divided by generation seconds.
For comparisons, generation-time ratio means generation seconds divided by audio seconds; lower is faster.
[Inspected model source](https://github.com/Blaizzy/mlx-audio/blob/2209e6d76c18d0a24f7ff64d35b4176258acd909/mlx_audio/tts/models/fish_drama3/drama3.py).

Inference: the first integration can reuse the player, waveform, gallery, templates, and operation status.
It needs its own capability declaration. AuK's required duration and Edit mode cannot transfer unchanged.
Reference transcripts also need an explicit source.

## Batching and memory

SGLang-Omni supports concurrent Drama-3 requests on NVIDIA hardware.
Its published tests reach 16 active streams with a mean generation-time ratio of 0.373 on one H200.
It also batches completed requests during codec decoding, within a memory limit.
This proves a server-side optimization path exists. It does not establish MLX batch performance.
[SGLang-Omni cookbook](https://github.com/sgl-project/sglang-omni/blob/main/docs/cookbook/fishaudio_drama3.md).

An open MLX Audio issue reports silent tails, early endings, and large cached codec buffers.
The author measured 110 GB of process footprint across 20 references with an unbounded cache.
A cache limit reduced that footprint, but one long chunk still reached 46.3 GB.
The issue also reports different reference-resampling results from Fish's reference implementation.
These are external reproduction results. I have not reproduced them.
[Issue #1026](https://github.com/Blaizzy/mlx-audio/issues/1026).

My assessment: begin with a resident model, reference reuse, bounded buffers, and streamed codec decoding.
Measure physical footprint and swap growth across repeated calls.
An HTTP batch endpoint alone does not prove simultaneous engine calculation or better throughput.

## Final office integration results

Drama-3 is available in the shared Voice selector, with Generate, Clone, script-target delivery templates,
44.1 kHz waveform selection/export, required reference transcript, and a 15-second reference limit.
AuK remains the default. Unsupported Design/Edit/duration controls are hidden by capabilities.

A real API batch of sixteen reference-conditioned clips completed in 49.83 seconds for 55.40 seconds
of audio, with all sixteen scripts confirmed by CPU speech recognition. Metal allocation stayed around
41.05 GiB during this batch. Warm four-item Clone batching was 9% slower than separate warm requests;
the implementation is ordered model/reference reuse, not concurrent tensor sampling.
Reference-conditioned Traditional Chinese completed in 4.22 seconds for 3.58 seconds of correct speech.
An unconditioned Chinese trial hit the token cap; general multilingual reliability is not established.

The upstream 300-byte internal chunk size caused long scripts to hit token limits. A matched adapter
trial with 180-byte chunks produced a complete 573-character Generate script in 27.20 seconds
(31.95 seconds of audio), and a complete 376-character Clone script in 30.31 seconds.
Both transcripts were checked in full. This setting is applied to the pinned engine's bound splitter
and to the adapter's completion validator. Internal chunks still produce one continuous gallery clip.

Real-model cancellation, recovery, partial-batch failure, two tabs and reloads passed. A live-weight
test passed. Full timings and source-bracketed evidence are in
[the benchmark report](../reports/dynamic-batching-drama3-2026-10-21/report.md).
